# sahinit runs sash services, batch 2: contract

2026-11-23. Branch `feat/sash-services-2`, from `feat/sash-services` (batch 1, `docs/design/sash-services-1.md`). Batch 2 adds the verbs batch 1 refused as `unsupported`:
- `mount` and `umount` (key `fs.mount`);
- the file verbs `mkdir`, `chown`, `chmod`, `touch`, `ln` and `rm` (key `file.write`, the operation in `argv[0]`).

As in batch 1, the authority for every rule is the sash contract, `docs/plans/2026-11-21-sash-init-contract.md` in the sash repository, in particular "Phase 1 build decisions" items 7, 10, 21, 22 and 23. The other references are:
- `internal/grant/policy.go`: the mount allowlists;
- `internal/proto/prototest/init.go`: the init double's checks;
- `internal/lang/svc.go`: the argv each verb arrives with.

sahinit copies the tables and does not import sash. `internal/sash/testdata/sash-mount-vectors.json` holds sash's own answers for a set of mounts and mount sources, generated by sash's `CheckMountOpts` and `AllowsMountSource`. A test compares sahinit's answers with them.

## Threats

These verbs need privileges that sash does not have, by design (decision B2: sash runs as the service's unprivileged uid). Mounting needs CAP_SYS_ADMIN. Creating a file the service then owns, or changing an owner, needs root. So sahinit performs them, **as root**, after its own checks. A check that is wrong here is a root-level write chosen by a service script, so every rule below is enforced by sahinit itself, never trusted from sash. The attacks considered:
- **Symlink swaps.** The service owns its `file_write` tree and can replace any component of a path with a symlink at any time. Every path is opened with `openat2(RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS)` from its root, which itself is opened with `RESOLVE_NO_SYMLINKS`. Each operation then works on the opened directory fd and a single final name: `mkdirat`, `symlinkat`, `unlinkat`, `fchownat(AT_SYMLINK_NOFOLLOW)`. chmod and touch act on an fd that was opened `O_NOFOLLOW` (by `/proc/self/fd`, never by path). A symlink at any component, the last included, is refused (`symlink`).
- **`..` and paths outside the roots.** A path must be absolute and clean and lie at or under a `file_write` root. `RESOLVE_BENEATH` refuses an escape the kernel sees.
- **A hard link out of the root.** A hard link inside `file_write` to a file elsewhere (`/etc/shadow`) would let chown, chmod or touch act on that file. Non-directories with more than one link are refused (`hardlink`).
- **A root-owned file chown.** chown and `mkdir owner` give a file only to the service's own identity: the grant's `user` and `group`, which must resolve to the unit's uid and gid. They never give it to root or another account. chown, chmod, touch and rm act only on a target the service already owns (a regular file or a directory, with one link if not a directory). A root-owned file under `file_write`, a secret placed there by root for example, is never given to the service, made readable, touched or removed by sahinit's root (`denied`). The one exception is a directory sahinit has just made for `mkdir`: it is the service's from the start. An existing directory with no mode and no owner asked for is left as it is.
- **setuid, setgid and devices.** Modes are at most 1777 (`chmod` and `mkdir mode`): never setuid or setgid. Every mount gets `nosuid,nodev` (sahinit refuses a mount whose options lack either). The options `suid`, `dev` and `exec` are not on the allowlist.
- **Mounting another tree in.**
  - The type must be on the allowlist (`tmpfs`, `proc`, `sysfs`, `devpts`), and a type mount's source is its type.
  - `overlay`, `lowerdir=`, `x-bind`, `move` and any other option are refused (`mount_opt_refused`).
  - A bind (`bind`, `rbind`) needs a path source equal to or beneath a `mount_sources` path. `/` can never be one: the grant refuses it.
  - The source and the mount point are resolved with `RESOLVE_NO_SYMLINKS` and mounted through their `/proc/self/fd` paths, so the checked inode is what gets mounted.
  - A mount point must be exactly one of the grant's `mounts`. It may not lie at or under a `file_write` root, nor hold one (`mount_overlap`). So a mount never lands in, or covers, the tree the service can write.
- **Create-then-chown races.** The service owns the directory sahinit creates in, so it can rename one of root's files into a new name between root's create and a chown by that name. So sahinit never chowns by name. It creates as the service: `mkdirat`, `symlinkat` and touch's `O_CREAT|O_EXCL` run on a locked OS thread whose filesystem uid and gid are the service's, with no supplementary groups. The thread's ids are restored and checked afterwards; a thread that cannot be restored ends and is never reused. mkdir's mode is set with `fchmod` on an fd that is checked to be a directory, owned by the service, with two links.
- **Remount and the superblock.** A remount changes only that mount's own flags (`MS_REMOUNT|MS_BIND`: ro, rw, nosuid, nodev, noexec). A size, `nr_inodes`, mode, uid or gid on a remount is `mount_opt_refused`, because a superblock may be shared with the host (sysfs) or with a bind's source.
- **Nested mounts of an rbind.** A bind is cloned with `open_tree` (recursively for rbind) and gets its flags with `mount_setattr`, on every nested mount too, before `move_mount` attaches it. On a kernel without these calls rbind is `unsupported`; a plain bind falls back to bind followed by a remount on the new mount.
- **Remount and umount act on sahinit's own mount.** Each mount's unique ID (`STATX_MNT_ID_UNIQUE`, or `STATX_MNT_ID` before Linux 6.8) is recorded in a table shared by all services. It is checked before a remount or umount (`not_mounted` on a mismatch). A mount point another service holds is `exists`. umount is a plain umount, so a mount in use is `busy` and stays. Only an rbind, whose nested mounts came with it and lie under no other tracked mount, is detached. The table is persisted atomically in the sash state directory with the boot ID. At start, sahinit removes what an earlier instance left on this boot, after checking each ID (`sash_mount_leftover`). Each service's mounts are unmounted, newest first, when it ends, stops or fails.
- **Check sessions** stay read-only: every batch 2 verb mutates and is `check_read_only` in a check session.

This does NOT confine what a legitimate mount exposes: a bind of a listed source is visible to everything in the host's mount namespace, as the signer allowed. Mounts are made in sahinit's own mount namespace.

## Verbs

| argv (from sash) | sahinit's checks and action |
| --- | --- |
| `mkdir PATH [mode M] [owner U:G]` | PATH under `file_write`; its parent exists (no recursion). Create with `mkdirat` (mode M, default 0755), or accept an existing directory (idempotent), then apply mode and owner. A non-directory there is `exists`. |
| `chown PATH U:G` | U:G is the grant's identity; target checks above; `fchownat(dirfd, name, AT_SYMLINK_NOFOLLOW)`. |
| `chmod PATH M` | M at most 1777; target checks above; chmod through the `O_PATH` fd. |
| `touch PATH` | Create (`O_CREAT|O_EXCL|O_NOFOLLOW`, 0644, owned by the service) or update the times of an existing regular file that passes the target checks. |
| `ln PATH TARGET` | Both under `file_write` (sash made TARGET absolute). `symlinkat(TARGET, dirfd, name)` and the link is owned by the service; TARGET is only the link's text. An existing name is `exists`. |
| `rm PATH` | A file, or an empty directory (`not_empty`), never recursive and never a `file_write` root itself. `unlinkat`, with `AT_REMOVEDIR` for a directory. A symlink is refused like any other. |
| `mount SRC DIR [type T] opts O` | The policy checks above, then `mount(2)`: a type mount directly, a bind as a bind followed by a remount applying `ro`, `nosuid`, `nodev` and `noexec`. |
| `umount DIR` | DIR is a mount this service made; `umount2(MNT_DETACH)`. |

`file.write` with any other `argv[0]` (the plain `> path` write) stays `unsupported`. Refusal tokens are `denied`, `symlink`, `hardlink`, `exists`, `not_empty`, `not_found`, `mount_opt_refused`, `mount_overlap`, `not_mounted` and `check_read_only`. sash prints `not_mounted` and `denied` as refusals; the rest are exit 1 `parent <key>`.

## Tests

- **Vectors:** the mount policy vector from sash.
- **Server refusals:** each check, in unit tests with a fake host.
- **End to end:** with the real sash binary, as root in Docker. A script makes, chowns, chmods, touches, links and removes files, and mounts a tmpfs and a bind, which are unmounted at stop. The attacks: a symlink swapped into a path, a bind of `/`, an overlay with `lowerdir=`, chown of a root-owned file reached through a hard link, `..` paths, and a hard link to a file outside the root.
- **Reverts:** every check has a test that fails when it is reverted.

## Decisions made during the build

1. **Vectors.** sash has no mount testdata, so `sash-mount-vectors.json` was generated by sash's own `CheckMountOpts` and `AllowsMountSource` (copied, unchanged, into a scratch module; the sash repository is not modified). It covers every type on the allowlist, `overlay`, `ext4` and `bpf`, and the option cases the contract names.
2. **Targets the service owns.** chown, chmod, touch and rm act only on a target the service already owns. This is stricter than "root or the service": a root-owned file under `file_write` is never given away, chmodded, touched or removed. A directory `mkdir` has just made is the service's. An existing directory with neither mode nor owner asked for is accepted as it is (idempotent), whoever owns it.
3. **Owner** (chown, `mkdir owner`) is only the grant's `user:group`, and the host checks that those names resolve to the unit's uid and gid. A new file (touch) is 0644 and a new link is owned by the service.
4. **Modes.** The form `[01]?[0-7]{3}` alone bounds a mode at 1777. A second numeric cap was redundant and is not kept.
5. **Mounts through `/proc/self/fd`.** The source and the mount point are opened with `RESOLVE_NO_SYMLINKS` and mounted by their `/proc/self/fd` paths. A bind's options need a remount, and it must be made on the new mount: the first build remounted through the fd opened before the bind, which names the directory beneath it. The mount point is now opened again for that remount.
6. **One mount per point.** A mount where any service already has one is `exists`: nothing is stacked. Unmounting is a plain umount (a detach only for an rbind), newest first, when the service stops, ends or fails, and before a new start.
7. **Trailing symlinks.** `O_PATH|O_NOFOLLOW` with `RESOLVE_NO_SYMLINKS` returns the link itself rather than refusing it. `sandbox.OpenBeneath` now leaves `O_NOFOLLOW` off an `O_PATH` open, so a trailing link is `ELOOP` (`symlink`). This also corrects batch 1: `probe file` on a symlink under `file_read` reported ready.
8. **Quoting in sash scripts.** sash refuses an unquoted option word holding `=` or `,` (`opts bind,ro` is a usage error, `opts size=1m` a parse error); scripts write `opts "bind,ro"`. This is sash's behaviour and is recorded for its documentation.
9. **Tokens.** sash prints `denied` and `not_mounted` as refusals (exit 2, `sash_config`). `symlink`, `hardlink`, `exists`, `not_empty`, `not_found`, `mount_overlap`, `busy` and `unsupported` reach sash as other parent errors (exit 1, `failed`, restart policy applies).
10. **The review's races, reproduced.** A racer at the service's fsuid renaming root's secret into the new name won against the first build's ln (after 241 attempts in our test) and mkdir (after 133). The regression tests run the same racer for up to 25 s and fail if root's file, under any name, ever becomes the service's, or if a directory of root's is ever chmodded.
11. **The sash state directory** is `--sash-floor-dir`: private to the supervisor, and already where sahinit keeps sash state. The mount table is `sash-mounts.json` there.
12. **Unique mount IDs.** Plain mount IDs are reused as soon as a mount is gone, so a mount an admin made in its place matched the recorded ID. The unique ID is used where the kernel has it.
13. **umount by path after the check.** An open fd on the mount would itself make it busy. So the ID is checked through an fd that is then closed, and the umount names the path with `UMOUNT_NOFOLLOW`. The mount point's parents are outside every `file_write` root, so the service cannot swap them in between.
14. **Touch** creates as the service, like mkdir and ln.
15. **One step from check to claim.** A mount point is reserved, with a pending record, under the same lock as the check that no record holds it, then filled in with its ID once mounted. Two services listing the same point cannot both mount it; the loser is `exists`.
16. **No mount without IDs.** Before mounting, sahinit reads a mount ID through the mount point's fd; a kernel without one is `unsupported`, so no mount is ever made that could not be checked again. If the ID cannot be read after mounting, the new mount is detached by its reserved path and the record dropped.
17. **Forgotten mounts.** A record whose mount is no longer the one sahinit made (`not_mounted` on umount or remount) is dropped and audited as `sash_mount_forgotten SERVICE DIR`, so the point is free again rather than `exists` until a restart.

## The PID 1 boot test

`scripts/test-boot.py --scenario sash` boots sahinit as PID 1 in QEMU with real sash services (`docs/host-init.md`, VM suite). Decisions:

1. **Init passes the sash options.** PID 1 started the supervisor with fixed arguments, so every sash unit was refused at load (`sash_fleet_key`), and strict boot made that a failed boot. `init` now takes `--sash`, `--sash-fleet-pub` and `--sash-floor-dir` (absolute) and passes them on when set.
2. **Ephemeral keys.** `tests/boot/sashfix` makes the fleet key in memory each time the images are built and writes only the public key, the grants and a floor document. The floor goes in through `sahinit sash floor-install`, the operator's path.
3. **The driver is outside the services.** The control socket refuses a peer in a service cgroup or a group a service led (`peer_supervised`). A root oneshot without a sandbox, which can leave its cgroup by design (`cgroup_trusted`), starts the driver with `setsid` and moves it to the root cgroup.
4. **The refused grant is on a non-boot unit.** Host mode makes every boot unit essential, so a refused grant on one enters recovery. The test starts the revoked unit with `ctl start` after boot and checks that boot and `svc` carry on.
5. **The spawned program is the probe.** The image has no shell or `sleep`; `/probe sleeper` is listed in the grant's `exec`, writes readiness to fd 3 and waits for TERM. It runs as nobody, so it never opens the console.
