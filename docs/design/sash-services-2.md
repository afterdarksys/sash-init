# sahinit runs sash services, batch 2: contract

2026-11-23. Branch `feat/sash-services-2`, from `feat/sash-services` (batch 1, `docs/design/sash-services-1.md`). Batch 2 adds the verbs batch 1 refused as `unsupported`:
- `mount` and `umount` (key `fs.mount`);
- the file verbs `mkdir`, `chown`, `chmod`, `touch`, `ln` and `rm` (key `file.write`, the operation in `argv[0]`).

As in batch 1, the authority for every rule is the sash contract, `docs/plans/2026-11-21-sash-init-contract.md` in the sash repository, in particular "Phase 1 build decisions" items 7, 10, 21, 22 and 23. The other references are:
- `internal/grant/policy.go`: the mount allowlists;
- `internal/proto/prototest/init.go`: the init double's checks;
- `internal/lang/svc.go`: the argv each verb arrives with.

sahinit copies the tables and does not import sash. `internal/sash/testdata/sash-mount-vectors.json` holds sash's own answers for a set of mounts and mount sources, generated by sash's `CheckMountOpts` and `AllowsMountSource`. A test compares sahinit's answers with them.

## Threats

These verbs need privileges that sash does not have, by design (decision B2: sash runs as the service's unprivileged uid). Mounting needs CAP_SYS_ADMIN. Creating a file the service then owns, or changing an owner, needs root. So sahinit performs them, **as root**, after its own checks. A check that is wrong here is a root-level write chosen by a service script, so every rule below is enforced by sahinit itself, never trusted from sash. The attacks considered:
- **Symlink swaps.** The service owns its `file_write` tree and can replace any component of a path with a symlink at any time. Every path is opened with `openat2(RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS)` from its root, which itself is opened with `RESOLVE_NO_SYMLINKS`. Each operation then works on the opened directory fd and a single final name: `mkdirat`, `symlinkat`, `unlinkat`, `fchownat(AT_SYMLINK_NOFOLLOW)`. chmod and touch act on an fd that was opened `O_NOFOLLOW` (by `/proc/self/fd`, never by path). A symlink at any component, the last included, is refused (`symlink`).
- **`..` and paths outside the roots.** A path must be absolute and clean and lie at or under a `file_write` root. `RESOLVE_BENEATH` refuses an escape the kernel sees.
- **A hard link out of the root.** A hard link inside `file_write` to a file elsewhere (`/etc/shadow`) would let chown, chmod or touch act on that file. Non-directories with more than one link are refused (`hardlink`). A file owned by anyone other than root or the service's uid is refused (`denied`).
- **A root-owned file chown.** chown and `mkdir owner` give a file only to the service's own identity: the grant's `user` and `group`, which must resolve to the unit's uid and gid. They never give it to root or another account. The target must be a regular file or a directory, owned by root or the service, with one link if not a directory.
- **setuid, setgid and devices.** Modes are at most 1777 (`chmod` and `mkdir mode`): never setuid or setgid. Every mount gets `nosuid,nodev` (sahinit refuses a mount whose options lack either). The options `suid`, `dev` and `exec` are not on the allowlist.
- **Mounting another tree in.**
  - The type must be on the allowlist (`tmpfs`, `proc`, `sysfs`, `devpts`), and a type mount's source is its type.
  - `overlay`, `lowerdir=`, `x-bind`, `move` and any other option are refused (`mount_opt_refused`).
  - A bind (`bind`, `rbind`) needs a path source equal to or beneath a `mount_sources` path. `/` can never be one: the grant refuses it.
  - The source and the mount point are resolved with `RESOLVE_NO_SYMLINKS` and mounted through their `/proc/self/fd` paths, so the checked inode is what gets mounted.
  - A mount point must be exactly one of the grant's `mounts`. It may not lie at or under a `file_write` root, nor hold one (`mount_overlap`). So a mount never lands in, or covers, the tree the service can write.
- **Remount and umount** act only on a mount this service made (`not_mounted`). sahinit tracks each service's mounts and unmounts them, newest first, when the service ends, stops or fails.
- **Check sessions** stay read-only: every batch 2 verb mutates and is `check_read_only` in a check session.

This does NOT confine what a legitimate mount exposes: a bind of a listed source is visible to everything in the host's mount namespace, as the signer allowed. Mounts are made in sahinit's own mount namespace.

## Verbs

| argv (from sash) | sahinit's checks and action |
| --- | --- |
| `mkdir PATH [mode M] [owner U:G]` | PATH under `file_write`; its parent exists (no recursion). Create with `mkdirat` (mode M, default 0755), or accept an existing directory (idempotent), then apply mode and owner. A non-directory there is `exists`. |
| `chown PATH U:G` | U:G is the grant's identity; target checks above; `fchownat(dirfd, name, AT_SYMLINK_NOFOLLOW)`. |
| `chmod PATH M` | M at most 1777; target checks above; chmod through the `O_PATH` fd. |
| `touch PATH` | Create (`O_CREAT|O_EXCL|O_NOFOLLOW`, 0644, owned by the service) or update the times of an existing regular file that passes the target checks. |
| `ln PATH TARGET` | Both under `file_write` (sash made TARGET absolute). `symlinkat(TARGET, dirfd, name)` and the link is owned by the service; TARGET is only the link's text. An existing name is `exists`. |
| `rm PATH` | A file, or an empty directory (`not_empty`), never recursive and never a `file_write` root itself. `unlinkat`, with `AT_REMOVEDIR` for a directory. A symlink is refused like any other. |
| `mount SRC DIR [type T] opts O` | The policy checks above, then `mount(2)`: a type mount directly, a bind as a bind followed by a remount applying `ro`, `nosuid`, `nodev` and `noexec`. |
| `umount DIR` | DIR is a mount this service made; `umount2(MNT_DETACH)`. |

`file.write` with any other `argv[0]` (the plain `> path` write) stays `unsupported`. Refusal tokens are `denied`, `symlink`, `hardlink`, `exists`, `not_empty`, `not_found`, `mount_opt_refused`, `mount_overlap`, `not_mounted` and `check_read_only`. sash prints `not_mounted` and `denied` as refusals; the rest are exit 1 `parent <key>`.

## Tests

- **Vectors:** the mount policy vector from sash.
- **Server refusals:** each check, in unit tests with a fake host.
- **End to end:** with the real sash binary, as root in Docker. A script makes, chowns, chmods, touches, links and removes files, and mounts a tmpfs and a bind, which are unmounted at stop. The attacks: a symlink swapped into a path, a bind of `/`, an overlay with `lowerdir=`, chown of a root-owned file reached through a hard link, `..` paths, and a hard link to a file outside the root.
- **Reverts:** every check has a test that fails when it is reverted.
